# 板端实验记录：2026-10-20

本轮按用户要求比较 `M=4096、N=4096、K=1024` GEMM 的不同优化方案，归 `board-testing` / 16号验证。
使用当前编译器重新生成各档实际产物，同一设备会话测量；属于策略对照，不是历史 commit 逐个重放。
原始样本、命令、输入/产物 hash、16 Tile IR 通信边、完整数值和设备日志检查见
[JSON](../data/board-performance/gemm-optimization-ladder-20261020.json)，汇总见
[CSV](../data/board-performance/gemm-optimization-ladder-20261020.csv)。
七档全部16 Tile的三层文本 IR、共同 source 及校验清单已一并保存，入口为
[IR 索引](../data/board-performance/gemm-optimization-ladder-20261020-ir/README.md)。

## 输入与计时

- `batch=1`，BF16；`A[1,4096,1024] × B[1,1024,4096] → C[1,4096,4096]`，
  seed `20260803`，单卡16 Tile。
- 每档三次串行实卡。Kernel 指每次16 Tile中最长的 main-entry duration，表中取三次中位数。
  包含 entry 内搬运、计算、通信与等待；不含独立 prepare、外层派发、主机准备和 H2D/D2H。
- 同次 TX stream event 单列，包含独立 prepare/派发等设备执行开销，不能与 kernel 混算加速比。
  NCx 的主机布局打包成本不在这两种计时区间内。
- 所有方案重新导出 source、构包并完成 no-card。逐文件 source hash 一致；
  Tensor/NCx raw 解码后的两份输入及完整 reference 逐字节相同。
- 保留同一 BF16/F32 累加语义、完整 PyTorch reference、相似度门槛和 memory guard；
  不启用 site Trace、PMU 或 Host 寄存器采集。

## 有效优化阶段

这四档用于展示不同优化能力下的性能改善。空间划分、计算分块和布局可能随策略一起变化，
阶段差值代表组合收益，不能解释成某个独立开关的净收益。

| 方案 | 实际优化内容 | Kernel 三次（ms） | Kernel 中位数（ms） | 相对基础版 | Event 中位数（ms） |
| --- | --- | --- | ---: | ---: | ---: |
| 基础分块 GEMM | 4×4 空间划分；各 Tile 独立读取，未做输入驻留/NoC 复用 | 3.582 / 3.522 / 3.537 | 3.537 | 1.00× | 4.508 |
| 本地驻留复用 | 16×1 空间划分；A 分片留在 SPM，跨 N 分块复用 | 2.807 / 2.693 / 2.862 | 2.807 | 1.26× | 3.743 |
| 非蛇形 NoC + 驻留复用 | 4×4 空间划分；B 驻留并按列直发，A 按行转发 | 2.174 / 2.255 / 2.186 | 2.186 | 1.62× | 3.516 |
| 蛇形 NoC + NCx 直接搬运 | 16×1 空间划分；B 沿相邻 Tile 蛇形转发，外部 NCx 与直接 blocked DMA | 1.814 / 1.784 / 1.794 | **1.794** | **1.97×** | 3.066 |

最终方案相对基础版 kernel 耗时下降 **49.3%**，相对非蛇形 NoC 组合下降 **17.9%**；
后者还包含 NCx 和分块变化，不能全部归因于蛇形拓扑。最终方案是本轮七档中最快的一档，
不声明对所有候选或其它 shape 全局最优。

仅调整分块和仅加入普通 NoC 的两档未取得收益，保留原始结果，不串入有效优化主表。
Tensor 蛇形结果也略慢于非蛇形驻留组合，不能声称单独改成蛇形就更快。
基线指不使用访问复用的实际合法分块候选，不等同于当前 `optimization-policy=none`。

两份自动结果的 actual DTE send/recv 均形成：

```text
0 → 1 → 2 → 3 → 7 → 6 → 5 → 4 → 8 → 9 → 10 → 11 → 15 → 14 → 13 → 12
```

这是对实际通信端点的检查；没有从名称推断实现，也不把端点链当作硬件内部路由的观测。
非蛇形版本的实际边、每 Tile GEMM 分块及 Instr hash 同样保存在 JSON。

## 验证与复现边界

- 七档共 **21/21** 次执行通过，每次比较全部 **16,777,216** 个 BF16 输出，检查 guard、
  16 Tile completion 和正常清理；按既有 cosine / relative L2 合同通过，不声称逐点 exact。
- 每次 launch 前检查系统占用，唯一设备持有者为已核实身份的厂商日志服务；同 boot、driver、runtime。
  所有执行窗口的诊断均无 fatal/timeout，未 reset/retry。
- 本轮未修改编译器或运行时，canonical 完整增量构建为 Ninja no-op。首次误用系统旧 CMake
  在读取 preset 时失败，换用仓库 managed CMake 后完成；没有建立第二个 build。
- 一个 `none` 策略探针虽已构包，却被现有 runner 的“每 Tile 单个 GEMM”专用结构断言拒绝，
  未进入 no-card、未上板、没有 timing；不计入上述七档及21次通过。未放宽或跳过该断言。
- 本轮只测用户指定的整除尺寸；未修改分块/尾部实现，也不借本轮结果重签其它 shape 或历史全矩阵。
- 编译源码为 `20e0f00b`；查询远程新增提交 `1ea76200` 只修改一个主机单测，不包含 GEMM 优化。
  构建工具 hash、boot/driver/runtime 身份、各次命令与全部测量顺序均在 JSON。
- 大型 package、raw 与日志保存在实验目录；Git 保存报告、CSV、原始样本、审计摘要、完整文本 IR 及产物身份，
  不把历史产物当作后续测试输入。
